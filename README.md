# Bean Import — 账单审阅与过账

本地 Express + React 工具，将支付宝、微信和银行流水与已有 Beancount 账本核对，再生成、校验和写入分录。

## 启动

需要 Node、pnpm，以及安装了 Beancount 的 Python 环境。优先使用账本自己的 `venv/bin/python` 或 `.venv/bin/python`。

```bash
pnpm install
pnpm dev
```

后端监听 `127.0.0.1:8787`，前端地址以 Vite 输出为准，通常为 `http://localhost:5173`。

构建后可由同一个后端提供页面：

```bash
pnpm build
pnpm start
```

访问 `http://localhost:8787`。Fava 为可选项，点击页面按钮时才启动。

## 账本配置

首次启动会查找工作区附近的 `accounting/main.bean`，并发现该账本的 Python 环境。已有的旧示例配置会迁移到发现的真实账本。本地配置、上传文件、分类记忆、批次和提交记录保存在忽略入库的 `server-data/`。

首次配置也可指定发现路径：

```bash
ACCOUNT_IMPORT_LEDGER_ROOT=/path/to/accounting ACCOUNT_IMPORT_PYTHON=/path/to/venv/bin/python pnpm start
```

已有配置可在页面“账本设置”修改；未提交批次审阅期间不能切换设置。`BEAN_IMPORT_DATA_DIR` 可指定独立的数据目录。Python 或账本入口不可用会明确报错，不会退回一个缺少账户的简化解析结果。

默认按年度输出：

```text
main.bean
years/2025/2025.bean
years/2025/imported/2025-09.bean
years/2026/2026.bean
years/2026/imported/2026-01.bean
```

写入时补充年度 include 链。导入文件独立保存，不向现有日常、旅行或周期交易文件中插入交易。关闭年度布局时，兼容 `monthlyDir/YYYYMM.beancount`。

## 审阅流程

1. 核对页面显示的目标账本、账户数和既有校验信息，上传已解压的 CSV / XLSX / PDF。
2. 每条原始交易保留来源行、交易号、状态、收支和支付方式。关闭、失败、未完成及零金额交易有排除原因；未知状态保持待审。
3. 资金账户按真实账户、卡尾号、借贷类型、交易日期和币种推断。钱包身份不明确、组合付款、优惠金额不明时需人工确认。
4. 展开“历史参考”查看已有账本的日期、商户、文件行号和分录。沿用历史分类与确认是否入账是独立操作。
5. 保存审阅结果，生成预览，再点击“校验并写入账本”。任何编辑都会使旧预览失效，未保存编辑会阻止生成和提交。

“选择”复选框用于批量操作，“入账”复选框决定是否生成分录。可对选中交易或当前筛选结果快速添加、移除标签，设置 `*` 正常或 `!` 待核实。标签和标记也可逐笔编辑；中文说明可写入审阅备注。

Beancount 原生标签使用英文字母、数字及 `_ . / -`，例如 `trip2026`、`refund`、`need-check`。`!` 标记与入账状态独立，一条待核实交易也可以在人工确认后写入。

多 posting 编辑支持优惠、代付及混合支付，使用带正负号的金额，每个币种须平衡。退款建议冲回原费用；还款、自有资金转移使用双方资产或负债账户。转账配对仅给建议，采用双腿分录后需明确排除对应的另一条流水。

## 重复导入与恢复

- 平台来源 + 交易号是确凿重复依据。无交易号的文件使用原始文件 SHA-256 + 行号识别原文件重放，保留同一文件中两条真实相同行。
- 历史账本缺少来源 ID 时，同日、同账户、同币种、同方向金额的记录作为候选展示，保持待审。相同金额不会自动删除交易。
- 相同交易已在其他未提交批次时，提示恢复原批次并展示参考，避免重复审阅。不同金额的同商户历史也可查看，仅供分类参考。
- 新分录保留来源、交易号或文件哈希、原始行、时间、导入批次、标签、标记和审阅备注，供后续查重。
- 批次及审阅结果落盘，重启后可继续；切换账本后只显示属于当前账本的批次。
- 提交仅接收批次版本，由服务端重新生成。写前对账本快照进行原生 Beancount 校验，拒绝新增错误、重复来源 ID、越界 include 和并发改动。
- 既有账本错误单独显示并作为基线，不会自动修复。提交记录保存文件变化；中断提交先恢复，重复提交返回原结果。

历史交易的来源时间窗可能重叠。按逐笔依据核对整批文件，不按账本最新日期统一截断。

## 验证

```bash
pnpm test
pnpm build
```

测试覆盖生产解析、原生账本读取、历史分类、资金映射、来源去重、人工转账建议、分录生成、暂存校验、中断恢复、审阅 API 和前端数据契约。API 集成测试在进程内运行真实 Express / Multer 中间件，不需要监听端口；所有测试写入使用临时账本。

本次 `20260905` 样本的完整性回归断言支付宝 1064 条、微信 444 条。私有样本不入库，可指定目录运行：

```bash
pnpm smoke /path/to/statements/20260905
pnpm test:statements /path/to/statements/20260905
```

这些命令仅读取原始样本及真实账本，将测试上传和批次写入临时目录，不提交至真实账本。

## 当前边界

银行 PDF 仍使用坐标网格解析，需以对应银行的真实样本核对。流水中的逐笔余额不会自动当成日终余额；只有明确证明完整日覆盖的记录才生成次日独立 `balance` 指令。交易日有效的已定义账户是生成候选，新账户需先在账本中明确定义。

暂存校验支持账本目录内的相对或绝对 include。越界、符号链接和通配 include 会明确拒绝，避免验证绕回真实账本。证券成本和跨币种兑换的手工分录仍应使用原账本工具维护。
